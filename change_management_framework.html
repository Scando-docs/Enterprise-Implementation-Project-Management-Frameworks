Change Management Framework

Controlling Scope, Schedule, and Budget | Standard Implementation Methodology

1. Introduction & Scope Control

During any enterprise software implementation, deviations from the initially approved scope (Blueprint/Requirements) are inevitable. However, uncontrolled changes (Scope Creep) are a primary cause of project failure, delays, and budget overruns. This framework defines a strict, standardized process for how changes are requested, assessed by the technical team, priced, and formally approved. No changes will be implemented in the system without an approved Change Request (CR) flowing through this exact procedure.

2. Change Execution Workflow & SLAs

To ensure swift but controlled decision-making, all changes must strictly adhere to the following procedural workflow:

1

Submission of Change Request (Originator)

The Client or Project Stakeholder identifies a new requirement and submits a formal Change Request using the standard email template (provided below) to the Project Manager and Technical Team.

2

Impact Assessment (Technical Team)

SLA: 5 Working Days
The Technical Team receives the request and analyzes the technical feasibility, system architecture impact, required effort, and budget implications. They document this in an Impact Assessment and determine the cost.

3

Submission for Approval (To Client PM / Sponsor)

The Technical Team sends the completed Impact Assessment, including the revised budget and schedule implications, to the Client Project Manager and/or Project Sponsor for review.

4

Approval and Acceptance (Client PM / Sponsor)

The Client PM or Sponsor reviews the budget and schedule impact. If accepted, they must reply to the Technical Team's impact assessment email with a formal written acceptance/approval.

5

Charter & Plan Update (Implementation Project Manager)

Once the approval email is confirmed, it is forwarded to the Implementation Project Manager. The Project Manager formally updates the Project Charter, the Master Project Plan, and the Budget to baseline the new scope.

6

Execution & Validation

The Technical Team executes the change in the system. The new feature/change is then validated by the client during standard User Acceptance Testing (UAT).

3. Change Request (CR) Email Form

To initiate step 1 of the workflow, please copy the template below, fill in the bracketed information, and email it to the Technical Team and Project Manager.

Subject: Project Change Request - [Brief Title of the Change]

Dear Technical Team & Project Management,

Please review the following Change Request for impact assessment:

1. Description of Change:
[Provide a detailed explanation of the new requirement or the change to existing scope. E.g., "Add a multi-level approval workflow for Purchase Orders exceeding $50,000."]

2. Business Justification:
[Explain why the standard functionality or previously agreed scope is insufficient. What is the business value/ROI of this change?]

3. Alternatives Considered:
[Are there any manual workarounds if this change is rejected? E.g., "We can track this in Excel, but it increases audit risk."]

4. Urgency/Target Phase:
[When is this change required by? E.g., "Must be included prior to UAT sign-off."]

Please provide the Impact Assessment, including budget and schedule implications, within the standard 5-working-day SLA.

Best regards,

[Your Name/Title]
[Client Organization]
